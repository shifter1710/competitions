# Отложенные идеи (не в активном плане)

Зафиксировано 2026-09-12. Эти задачи **не запланированы** — возвращаемся к ним,
только если продукт пойдёт дальше одного оператора и появится кому нести
эксплуатацию.

## Аутентификация: слой провайдеров + флаг локального входа

Если вуз захочет входить своими учётками:

- внутренний провайдер — текущие логин/пароль из БД, работает из коробки;
- OIDC-провайдер (issuer, client_id, client_secret через env): первый вход
  создаёт локального пользователя с ролью athlete, роли назначает локальный
  админ;
- флаг `AUTH_LOCAL_LOGIN_ENABLED=false` отключает парольный вход, аварийный
  локальный админ остаётся;
- при необходимости LDAP/CAS — отдельной обёрткой поверх того же интерфейса.

**Не хотим**: email/телефоны у учёток, самостоятельную регистрацию,
восстановление пароля по почте. Учётками управляет админ вручную —
для доверенного круга это проще и безопаснее.

## Импорт Excel с маппингом колонок

Импорт требует точного совпадения заголовков с шаблоном; файл с другими
названиями колонок отвергается с «Missing required columns». Решение при
необходимости — экран сопоставления «колонка файла → поле системы»
с запоминанием выбора в браузере. **Возвращаемся только если оператор
реально упрётся в эту ошибку** со своим накопленным файлом.

## Документация «быстрый старт» для чужого инстанса

Пошаговая инструкция: свой сервер → docker compose → .env → nginx + Let's Encrypt
→ включить бэкап-таймер. Нужна только если системой заинтересуется другой вуз.

## Позиционирование (принято)

- Один изолированный инстанс на организацию; общей мультиарендной платформы
  с центральным доменом не делаем.
- Ответственность за персональные данные (оператор по 152-ФЗ, согласия
  студентов, сроки хранения) несёт организация-владелец инстанса,
  а не разработчик.
- Поддержка чужих внедрений не предполагается: код и документация — да,
  настройка и сопровождение — нет.
