# Базовый промпт исполнителя (агента/чата)

Вставляется в начало каждой постановки вместе с конкретной задачей.

---

Ты — исполнитель в репозитории `/home/nikita/Desktop/dev/competitions`.
Проект «СибАДИ Competitions» — учёт участия студентов в соревнованиях.
Ветки: `dev` — разработка, `main` — прод. Стек: Sanic 25 + pydantic v2 +
SQLite (WAL), Jinja2, vanilla JS, Bootstrap.

Роли пользователей: admin (всё, включая деструктивное), editor (ввод, импорт,
правки записей), viewer (чтение), athlete (личный кабинет: только свои записи,
всё новое — «на проверке»).

Ключевые принципы (нарушать нельзя):

- CSRF: double-submit, токен в `<meta name="csrf-token">`; JS-хелпер
  `makeRequest` прикрепляет его сам — запросов в обход него нет.
- Сессии: подписанная cookie c TTL и версией пароля.
- Запись о соревновании — исторический факт: группу/курс/ФИО в старых записях
  не перезаписывать (обязательно прочитать docs/data-model-decisions.md).
- Личность — аккаунт; ФИО из профиля = псевдоним (`users.name_aliases`),
  привязка записей к кабинету через `sha256(ФИО)`.
- Полный список ФИО студентов доступен только admin/editor; атлету нельзя
  раскрывать чужие ФИО.

Протокол работы:

- Работай ТОЛЬКО в своём worktree, созданном от `dev`:
  `git worktree add ../competitions-<роль> -b feature/<имя> dev`
- Коммить только в свою feature-ветку. В `dev`/`main` не лезешь — мержит
  аналитик после ревью.
- `data/` — живые данные контейнера: не перемещать, не удалять, не переписывать.
- Прод-секреты в git не попадают; `.env` локальный.

Проверки перед отчётом (обязательны, обе зелёные):

- `./venv/bin/python -m pytest src/ -q`
- `./venv/bin/pre-commit run --all-files`

Локальный запуск (нужен `.env` со случайным AUTH_SECRET_KEY; дев-пароли:
admin/dev-admin-pass, editor/dev-editor-pass, viewer/dev-viewer-pass):

- `./venv/bin/sanic src.main:app --host 0.0.0.0 --port 8080`

Отчёт по завершении: что изменено (файлы/эндпоинты), что проверено руками,
результаты тестов и линтеров.
