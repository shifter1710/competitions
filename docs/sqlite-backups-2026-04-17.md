# SQLite backups — прежняя схема (17 апреля 2026)

Этот документ описывал одиночные gzip/ZIP и ротацию по числу запусков.
После BACKUP-02 актуальная инструкция —
[backup-reliability.md](backup-reliability.md).

Новые копии хранятся комплектами `sets/<id>/` с `manifest.json`,
`database.sqlite3.gz` и `files.zip`. `--keep` больше не включает удаление.
Старые плоские архивы сохранены, но не получают автоматически статус `Verified`
и не отправляются новым selector как полные проверенные комплекты.

Не используйте прежний рецепт распаковки поверх `data/` и удаления WAL/SHM.
Для любого восстановления сначала сохраните текущие данные, остановите запись
при согласованной замене и проверьте восстановление в отдельном окружении.
Изолированные CLI не заменяют production-БД.

SQLite online backup API сохраняется: полученный снимок учитывает committed
WAL-изменения. Это свойство снимка SQLite не означает атомарность с вложениями.
