# Переход на React: решение и план миграции

Принято владельцем 2026-09-12 (после анализа рисков; альтернатива
«редизайн на текущем стеке» отклонена в пользу полного перехода).
Новая постановка владельца: новый дизайн в Figma → переход на него
в рамках переезда фронтенда на React.

## Принятые рамки

- Целевой стек: Sanic (бэкенд, без изменений модели данных и бизнес-логики)
  + JSON API + React SPA (Vite-сборка), тёмная/светлая темы из одних
  дизайн-токенов.
- Модель данных, роли, историчность записей, приватность ФИО,
  CSRF-принципы — переносятся как есть; все решения
  docs/data-model-decisions.md остаются в силе.
- Стратегия: поэтапная (strangler-fig), НЕ big-bang: старый Jinja-фронт
  живёт и работает до полного выката React-версии; каждый этап — отдельный
  мерж в dev с зелёными тестами и QA-точкой.

## Фазы

0. **Дизайн (Figma).** Концепт ключевых экранов: вход, таблица, карточка
   записи/модерация, отчёт, кабинет атлета, хаб админа + подстраницы.
   Дизайн-токены: палитра (светлая/тёмная), типографика, отступы,
   компоненты (таблица, формы, бейджи статусов, диалоги). Ревью владельца
   на каждом экране. Выход: утверждённый дизайн + таблица токенов.
1. **JSON API.** Рядом с HTML-роутами появляется /api/v1/*: записи
   (CRUD + модерация), справочники, пользователи/алиасы/merge, обслуживание,
   аудит, отчёт, профиль, импорт, вложения. CSRF для API: double-submit
   токеном из meta (как сейчас) — те же гарантии. Auth — та же cookie
   (SameSite=Lax, same-origin SPA). Выход: API покрыт pytest-контрактом,
   старый фронт не тронут.
2. **Каркас React.** Vite + React + TypeScript, роутинг, API-клиент с CSRF,
   тема из токенов, скелет страниц, сборка в Docker (multi-stage), Sanic
   раздаёт сборку. Страница-пилот: /login. QA-точка: логин работает в обоих
   мирах, тесты зелёные.
3. **Миграция страниц** (порядок по ценности): таблица записей (инлайн-правка,
   колонки, фильтры) → кабинет атлета/профиль → отчёт → админ-страницы →
   импорт → merge/обслуживание/аудит. Каждая страница — отдельная ветка,
   ревью, QA-сценарии. Переключение страниц на React — за флагом на сервере
   (env), откат = выключить флаг.
4. **Вырезание старого.** Когда все экраны живут на React и QA-матрица
   (включая браузерный CSRF-блок) зелёная: удалить Jinja-шаблоны страниц
   (API и audit остаются), флаг убрать. Полный QA-прогон + деплой.

## Риски и как с ними обращаемся

- Объём: фазы 1–3 сопоставимы с 2–3 «вторыми волнами». Не стартуем фазу N+1,
  пока фаза N не смержена и не принята QA.
- CSRF-класс багов (как инцидент 2026-09-12): API-клиент — единственная
  точка прикрепления токена; браузерный блок в QA-матрице обязателен с
  первой React-страницы.
- Регресс UI: приёмка каждой страницы по чек-листу из Figma-экрана.
- Зависимость от npm-экосистемы: package-lock в git, аудит зависимостей
  в CI, минимум зависимостей (роутер, таблицу пишем свою — она уже
  наполовину кастомная в JS).
- Откат: до фазы 4 старый фронт цел; флаг переключения страниц.

## Что НЕ входит

- Изменение ролей/прав, модели данных, storage-слоя, экспортной логики
  xlsx (остаётся серверной), nginx-схемы деплоя (кроме раздачи сборки
  статики React).
- Самостоятельная регистрация/email — по-прежнему нет (future-ideas.md).
