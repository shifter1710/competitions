## №23. Календарь соревнований (уточнение модели, 2026-09-13)

Владелец уточнил: нужен НЕ справочник-пресет, а КАЛЕНДАРЬ. Поток:
1. Запланировать соревнования заранее на весь год (название, даты,
   уровень, вид спорта, ссылка).
2. Зайти «внутрь» соревнования → заполнять участников: ФИО с
   поиском по первым буквам (варианты из уже известных атлетов),
   институт/группа/пол подтягиваются автоматически из профиля атлета,
   место/результаты — сразу или ПОЗЖЕ.

Это меняет ранее предложенную модель «справочник-пресет с копированием»
на двухсущностную: КАЛЕНДАРЬ (план на год) + участники внутри
соревнования. Записи в реестре остаются историческими фактами;
соревнование без занесённых результатов — обычное состояние
(место=0/пусто, фильтр «без результата»). Прежние вопросы (роли,
копирование) пересматриваются под новую модель.

## №24. Привязка ссылки к другой колонке (2026-09-13, возврат №3)

Ссылка (кастомное поле типа link) должна уметь «прикрепляться» к другой
колонке таблицы: например, привязать «Ссылка на соревнование» к колонке
«Название соревнований» — тогда название становится гиперссылкой, а
отдельная колонка URL из таблицы уходит (данные остаются в выгрузке).

Предварительная конструкция (аналитик): настройка у link-поля —
«показывать в колонке: <выбор>» (field_settings/link-атрибут). Рендер
таблицы: в целевой колонке ячейка записи оборачивается в <a href=значение
этой записи>, если ссылка у записи заполнена; без ссылки — обычный текст.
Ссылки в выгрузке xlsx остаются колонкой данных. В правке/инлайне ссылка
редактируется в своём поле как сейчас.
